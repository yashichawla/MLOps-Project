# Metrics API Service Documentation

## Overview

The Metrics API Service is a FastAPI application deployed on Google Cloud Run that provides REST endpoints to access evaluation metrics stored in Google Cloud Storage. The service reads metrics files generated by the Airflow DAG (pushed via DVC) and exposes them via HTTP API for consumption by dashboards and other clients.

## Architecture

- **Data Source**: GCS bucket `gs://mlops-project-dvc/data/metrics/` and `data/bias/`
- **Service**: FastAPI application on Cloud Run
- **Authentication**: GCP Service Account with GCS read permissions

## Prerequisites

- GCP project with Cloud Run API enabled
- Service account with GCS read permissions (`roles/storage.objectViewer` on `gs://mlops-project-dvc`)
- Docker installed (for local testing)
- `gcloud` CLI configured
- Python 3.11+
- GCP service account key with GCS read permissions
- Access to GCS bucket `gs://mlops-project-dvc`

## Service Account Setup

1. Create a service account (or use existing):
```bash
gcloud iam service-accounts create metrics-api-sa \
  --display-name="Metrics API Service Account"
```

2. Grant GCS read permissions:
```bash
gcloud projects add-iam-policy-binding break-the-bot \
  --member="serviceAccount:metrics-api-sa@break-the-bot.iam.gserviceaccount.com" \
  --role="roles/storage.objectViewer"
```

The Cloud Run service uses the service account `dvc-airflow@break-the-bot.iam.gserviceaccount.com` which has:
- Read access to GCS bucket `gs://mlops-project-dvc`
- This allows the API to read metrics and bias reports from GCS

## Local Development Setup

1. Install dependencies:
```bash
cd deploy
pip install -r requirements-api.txt
```

2. Set environment variables:

**Windows (PowerShell):**
```powershell
$env:GOOGLE_APPLICATION_CREDENTIALS=".secrets/gcp-key.json"
$env:GCS_BUCKET="mlops-project-dvc"
$env:GCP_PROJECT_ID="break-the-bot"
$env:PORT="8080"
```

**Windows (CMD):**
```cmd
set GOOGLE_APPLICATION_CREDENTIALS=.secrets\gcp-key.json
set GCS_BUCKET=mlops-project-dvc
set GCP_PROJECT_ID=break-the-bot
set PORT=8080
```

**Linux/Mac:**
```bash
export GOOGLE_APPLICATION_CREDENTIALS=".secrets/gcp-key.json"
export GCS_BUCKET="mlops-project-dvc"
export GCP_PROJECT_ID="break-the-bot"
export PORT="8080"
export CORS_ORIGINS=*
```

3. Run the service:
```bash
cd ..
python -m uvicorn deploy.api.main:app --host 0.0.0.0 --port 8080 --reload
```

4. Test the service:
```bash
curl http://localhost:8080/health
curl http://localhost:8080/metrics/all
```

## Docker Build

Build the Docker image locally:

```bash
docker build -t metrics-api:local ./deploy
```

Run locally:

```bash
docker run -p 8080:8080 \
  -e GCS_BUCKET=mlops-project-dvc \
  -e GCP_PROJECT_ID=break-the-bot \
  -e GOOGLE_APPLICATION_CREDENTIALS=/secrets/gcp-key.json \
  -v /path/to/gcp-key.json:/secrets/gcp-key.json \
  metrics-api:local
```

## API Endpoints

### Health Check

#### `GET /health`

Check service health and GCS connectivity.

**Response:**
```json
{
  "status": "healthy",
  "gcs_connected": true,
  "bucket": "mlops-project-dvc",
  "timestamp": "2025-01-15T10:30:00Z"
}
```

### Metrics Endpoints

#### `GET /metrics/all`

Get summary for all available models.

**Response:**
```json
{
  "models": [
    {
      "model_name": "llama-3-8b",
      "coverage": {
        "total_prompts": 100,
        "num_categories": 5
      },
      "global_asr": 0.75,
      "over_refusal_rate": 0.12
    }
  ],
  "timestamp": "2025-01-15T10:30:00Z"
}
```

#### `GET /metrics/{model_name}`

Get full metrics for a specific model.

**Parameters:**
- `model_name` (path): Name of the model (e.g., `llama-3-8b`)

**Response:**
```json
{
  "model": "llama-3-8b",
  "coverage_metrics": {
    "total_prompts": 100,
    "num_categories": 5,
    "prompts_per_category": {...},
    "prompts_per_size": {...}
  },
  "over_refusal_metrics": {
    "threshold": 0.7,
    "safe_count": 20,
    "over_refusal_count": 3,
    "over_refusal_rate": 0.15
  },
  "timestamp": "2025-01-15T10:30:00Z"
}
```

#### `GET /metrics/{model_name}/bias`

Get bias detection report for a specific model.

**Response:**
```json
{
  "model": "llama-3-8b",
  "global": {
    "asr": 0.8,
    "mean_refusal": 0.14,
    "count": 100
  },
  "thresholds": {
    "relative_asr_deviation": 0.2,
    "min_count": 0
  },
  "by_category": [...],
  "by_size_label": [...],
  "biased_slices": {
    "category": [...],
    "size_label": []
  }
}
```

#### `GET /metrics/{model_name}/summary`

Get combined summary (metrics + bias) for a specific model.

**Response:**
```json
{
  "model": "llama-3-8b",
  "summary": {
    "total_prompts": 100,
    "global_asr": 0.8,
    "over_refusal_rate": 0.15,
    "biased_categories_count": 2,
    "biased_sizes_count": 0
  },
  "coverage": {...},
  "bias": {...},
  "timestamp": "2025-01-15T10:30:00Z"
}
```

### Dashboard Endpoints

#### `GET /dashboard/models`

List all evaluated models with metadata.

**Response:**
```json
{
  "models": [
    {
      "name": "llama-3-8b",
      "has_metrics": true,
      "has_bias_report": true,
      "last_updated": "2025-01-15T10:30:00Z"
    }
  ],
  "timestamp": "2025-01-15T10:30:00Z"
}
```

## Error Responses

### 404 Not Found

```json
{
  "error": "Metrics not found for model: invalid-model",
  "status_code": 404,
  "path": "/metrics/invalid-model"
}
```

### 500 Internal Server Error

```json
{
  "error": "Internal server error",
  "detail": "Error message",
  "path": "/metrics/llama-3-8b"
}
```

### 503 Service Unavailable

Returned when GCS connectivity fails.

## GCS Path Structure

The service reads from these GCS paths:

- Metrics: `gs://mlops-project-dvc/data/metrics/additional_metrics_{model_name}.json`
- Bias reports: `gs://mlops-project-dvc/data/bias/{model_name}/bias_report.json`

## CORS Configuration

CORS is configured to allow requests from any origin by default. To restrict to specific origins, set the `CORS_ORIGINS` environment variable:

```bash
export CORS_ORIGINS=https://your-streamlit-app.com,https://another-domain.com
```

## Environment Variables

The service uses these environment variables:

- `GCS_BUCKET`: GCS bucket name (default: `mlops-project-dvc`)
- `GCP_PROJECT_ID`: GCP project ID (default: `break-the-bot`)
- `PORT`: API port (default: `8080`)
- `CORS_ORIGINS`: CORS allowed origins (default: `*`)

## Troubleshooting

### GCS Connection Issues

- Verify service account has `storage.objectViewer` permission
- Check that GCS bucket name is correct
- Ensure service account key is properly configured

### Missing Models

- Verify that DAG has run and pushed metrics to GCS
- Check GCS bucket paths match expected structure
- Use `/dashboard/models` endpoint to list available models

### Invalid JSON Errors

- Check that metrics files in GCS are valid JSON
- Verify file encoding (should be UTF-8)

### API won't start
- ✅ Check GCP credentials exist at `.secrets/gcp-key.json`
- ✅ Verify bucket name: `mlops-project-dvc`
- ✅ Check port 8080 is not in use: `netstat -an | findstr ":8080"` (Windows) or `netstat -an | grep 8080` (Linux/Mac)

### API returns errors
- Check API terminal for error messages
- Verify GCS bucket is accessible
- Ensure metrics files exist in GCS

### Permission Errors
- **Cloud Build**: Ensure you have `Cloud Build Service Account` role or `Service Usage Admin` role
- **GCS Access**: The service account needs `storage.objectViewer` on the bucket
- **Container Registry**: Ensure Container Registry API is enabled

### Service Not Starting
Check logs:
```bash
gcloud run services logs read metrics-api --region us-central1
```

### API returns 404
- Verify metrics exist in GCS bucket
- Check model names match exactly
- Review API logs for errors
